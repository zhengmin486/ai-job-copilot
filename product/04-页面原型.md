# 04 核心页面低保真原型

> 只画骨架和状态，不画视觉稿，不写配色字号。
> 前四页对着 `front/app` 里真实存在的路由；后两页是路线图里的候选页，当前仓库未实现，
> 用来表达「配置引导」和「反馈闭环」两个产品判断，见 [08-路线图与风险合规](08-路线图与风险合规.md)。
> 字段名用中性占位，不放真实数据。
> 可打开的线框在 [prototype.html](prototype.html)，浏览器直接开，不用装东西。

## 选哪几页

| 页面 | 路由 | 为什么是核心 |
| --- | --- | --- |
| 岗位分析 | `/boss/analysis` | 看抓回来什么、被过滤掉多少，是「投得准」的入口 |
| 简历中心 | `/resume-center` | 附件版本和人工门都在这，发错版本的事故源头 |
| 投递记录 | `/records/all` | 复盘和去重的依据，查得到才算闭环 |
| AI 配置 | `/ai-config` | 判投不投和写招呼语的规则都从这里进 |
| 首次配置检查 | 候选页，未实现 | 首次配置是落地的主要卡点，检查清单能把「缺一项就跑不起来」变得可见 |
| 复盘与规则效果 | 候选页，未实现 | 反馈闭环的界面形态，对应指标树和提示词版本评测 |

首页、各平台配置页、环境配置页不是不做，是它们都属于「填参数」，骨架重复，这版不画。后两页明确标注为候选，免得把设计提案读成已实现功能。

## 一、岗位分析

```
+--------------------------------------------------------------+
| 侧栏 | 页头  岗位分析                             [刷新]    |
+------+-------------------------------------------------------+
|      | 筛选  平台 / 状态 / 关键词                 [查询]    |
|      +-------------------------------------------------------+
|      | 抓到 -- | 通过 -- | 跳过 -- | 待人工 --             |
|      +-------------------------------------------------------+
|      | 岗位名    公司    城市   经验   状态    操作        |
|      | 示例岗位A 公司A   城市A  不限   通过    [查看]     |
|      | 示例岗位B 公司B   城市B  不限   跳过    [原因]     |
|      | 示例岗位C 公司C   城市C  不限   待人工  [转定制]   |
|      +-------------------------------------------------------+
|      | 上一页   1 / --   下一页                             |
+--------------------------------------------------------------+
```

| 区域 | 元素 | 状态 | 交互 |
| --- | --- | --- | --- |
| 筛选 | 平台、状态、关键词 | 默认全部 | 查询后刷新列表，不自动开始投递 |
| 统计条 | 抓到、通过、跳过、待人工 | 无数据时显示占位横线，不显示零 | 点击数字可当筛选条件 |
| 列表 | 岗位名、公司、城市、经验、状态、操作 | 通过 / 跳过 / 待人工 / 已投 | 跳过行能看原因，待人工行转定制队列 |
| 分页 | 上下页、页码 | 只有一页时禁用 | 不记住筛选条件以外的状态 |

要表达的重点是「跳过」和「待人工」这两类，不是列表多好看。统计条不显示零，是因为空结果和真的零容易混。

## 二、简历中心

```
+--------------------------------------------------------------+
| 侧栏 | 页头  简历与人工门                                   |
+------+-------------------------------------------------------+
|      | 上传区   选择附件文件            [上传]         |
|      +-------------------------------------------------------+
|      | 版本      方向        文件        状态    操作      |
|      | 版本A     方向A       附件A.pdf   已就绪  [预览]   |
|      | 版本B     方向B       附件B.pdf   已就绪  [预览]   |
|      | 版本C     方向C       --          缺文件  [补传]   |
|      +-------------------------------------------------------+
|      | 映射规则  方向 -> 附件版本                 [保存]   |
|      +-------------------------------------------------------+
|      | 人工门    需要人确认后再投   [开 / 关]              |
+--------------------------------------------------------------+
```

| 区域 | 元素 | 状态 | 交互 |
| --- | --- | --- | --- |
| 上传区 | 文件选择、上传 | 未选 / 上传中 / 成功 / 失败 | 失败给原因，不静默吞掉 |
| 版本列表 | 版本名、方向、文件、状态 | 已就绪 / 缺文件 / 已停用 | 缺文件的方向不允许开投 |
| 映射规则 | 方向到附件版本的对应 | 未配 / 已配 | 保存后立刻生效，不重启 |
| 人工门 | 开关 | 开 / 关 | 开着的时候任务停在待确认，等人放行 |

「缺文件」这行是故意留的。没有对应附件就不投，得在界面上看得见，不能只写进代码里。

## 三、投递记录

```
+--------------------------------------------------------------+
| 侧栏 | 页头  投递记录                             [导出]    |
+------+-------------------------------------------------------+
|      | 筛选  平台 / 日期 / 结果                  [查询]    |
|      +-------------------------------------------------------+
|      | 岗位      公司    平台    附件版本   结果    时间  |
|      | 示例岗位A 公司A   平台A   版本A      成功    --    |
|      | 示例岗位B 公司B   平台B   版本B      失败    --    |
|      | 示例岗位C 公司C   平台C   --        跳过    --    |
|      +-------------------------------------------------------+
|      | 点一行展开：招呼语 / 失败原因 / 岗位来源            |
+--------------------------------------------------------------+
```

| 区域 | 元素 | 状态 | 交互 |
| --- | --- | --- | --- |
| 筛选 | 平台、日期、结果 | 默认全部 | 查询不改变后端数据 |
| 列表 | 岗位、公司、平台、附件版本、结果、时间 | 成功 / 失败 / 跳过 / 待确认 | 展开看招呼语和失败原因 |
| 空状态 | 提示文案 | 无记录时显示引导，不显示空白表格 | 引导去配置页 |
| 导出 | 导出按钮 | 无数据时禁用 | 只导出当前筛选结果 |

「跳过」也要进记录。不然复盘的时候只会看到投出去的，看不出哪些被规则挡了。

## 四、AI 配置

```
+--------------------------------------------------------------+
| 侧栏 | 页头  AI 配置                                        |
+------+-------------------------------------------------------+
|      | 接口地址  [ 占位 ]                                   |
|      | 密钥      [ 占位 ]                    [显示 / 隐藏] |
|      | 模型      [ 占位 ]                                   |
|      +-------------------------------------------------------+
|      | 自我介绍  [ 多行文本占位 ]                          |
|      +-------------------------------------------------------+
|      | 提示词    [ 多行文本占位，含若干个占位符 ]          |
|      +-------------------------------------------------------+
|      |                            [保存]  [试跑一次]       |
|      | 状态提示：未配置 / 已保存 / 调用失败 + 原因          |
+--------------------------------------------------------------+
```

| 区域 | 元素 | 状态 | 交互 |
| --- | --- | --- | --- |
| 接口 | 地址、密钥、模型 | 未配置 / 已配置 | 密钥默认掩码，不回显明文到日志 |
| 自我介绍 | 多行文本 | 占位 / 已填 | 只在本机保存 |
| 提示词 | 多行文本、占位符说明 | 占位 / 已填 | 留空时走内置默认模板 |
| 操作 | 保存、试跑 | 保存中 / 已保存 / 失败 | 试跑只生成不投递 |
| 状态提示 | 一行文字 | 成功 / 失败 / 未配置 | 失败要给原因，不能只写「失败」 |

「试跑一次」只生成、不投递，是这页最要紧的一条。改了 prompt 直接拿真实岗位去发，出事不好收。

## 五、首次配置检查（候选页）

```
+--------------------------------------------------------------+
| 侧栏 | 页头  首次配置检查                    [重新检查]     |
+------+-------------------------------------------------------+
|      | 完成度  -- / --                                       |
|      +-------------------------------------------------------+
|      | [v] 本机数据库       已就绪                          |
|      | [v] 平台登录态       已就绪          [去扫码]        |
|      | [ ] 平台搜索条件     未配置          [去填]          |
|      | [ ] 附件版本与映射   缺一项          [去补]          |
|      | [ ] AI 配置          可选，未配置    [去填]          |
|      +-------------------------------------------------------+
|      | 有未通过项时不显示启动入口，逐项给跳转               |
+--------------------------------------------------------------+
```

| 元素 | 判据 | 状态 | 交互 |
| --- | --- | --- | --- |
| 完成度 | 已通过项除以必需项 | 未就绪 / 可启动 | 不用数字进度条制造已完成感 |
| 检查项 | 数据库、登录态、搜索条件、附件映射、AI 配置 | 已就绪 / 未配置 / 缺一项 | 每项直接跳到对应配置页 |
| 可选项 | AI 配置 | 标「可选」 | 不阻塞启动 |
| 启动入口 | 全部必需项通过才出现 | 隐藏 / 可点 | 缺项时给原因，不静默禁用 |

这页解决的是「首次配置门槛高」的产品问题，不是加一个向导。检查清单的价值在于把失败前置，让缺项在启动之前就可见。

## 六、复盘与规则效果（候选页）

```
+--------------------------------------------------------------+
| 侧栏 | 页头  复盘与规则效果                   [导出样本]   |
+------+-------------------------------------------------------+
|      | 规则        拦截数   放行后结果   误拦复核   操作    |
|      | 硬要求拦截   --       --           --        [抽样] |
|      | 去重拦截     --       --           --        [抽样] |
|      | AI 拒绝      --       --           --        [抽样] |
|      +-------------------------------------------------------+
|      | 提示词版本对照   版本A / 版本B   [跑同一组回归用例] |
|      +-------------------------------------------------------+
|      | 结论区  哪条规则要收紧或放宽，写依据，不自动改配置 |
+--------------------------------------------------------------+
```

| 元素 | 说明 | 状态 | 交互 |
| --- | --- | --- | --- |
| 规则统计 | 每条规则拦了多少、放行后结果如何 | 有数据 / 无数据 | 点抽样看具体样本 |
| 误拦复核 | 人工标注被拦错的样本 | 待复核 / 已标注 | 标注结果进回归样本 |
| 版本对照 | 两组提示词跑同一组用例 | 未跑 / 已跑 | 只展示对比，不自动切换 |
| 结论区 | 写调整依据 | 空白 / 已写 | 不提供一键改配置 |

这页是反馈闭环的界面形态，对应 [07-需求分析与取舍](07-需求分析与取舍.md) 的指标树和 [06-AI设计与评估](06-AI设计与评估.md) 的上线门槛。**刻意不做自动调参**：规则一旦能自行放松，护栏就失去意义。

## 线框文件

[prototype.html](prototype.html) 是一个自包含 HTML，六个页面用顶部标签切换，纯灰阶线框，没有外部依赖。它只表达布局和状态，不是能跑的界面，也不要拿它当视觉稿。
